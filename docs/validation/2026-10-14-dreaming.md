The Electron launch failure recorded earlier (`Process failed to launch` / `kill EPERM`) did not reproduce. Electron 44.7.2 is fully installed in this checkout, and the desktop test passed on every run.

**Model boundary.** The production runner is tested through the real OpenAI-compatible adapter against a controlled HTTP endpoint. That adapter sends `response_format: json_object` without a schema, so the test asserts that the JSON Schema is stated in the request messages. It also checks that no tools are sent, the output limit is 3,000 tokens, there is exactly one attempt on a 503, and output that ignores the shape is rejected. A second test checks that recalled memory reaches text-only chat as untrusted data and that the memory-proposal tool is hidden while dreaming is on.

**Browser acceptance.** This uses the deterministic fixture `dreamRunner` in `e2e/server.ts`: "Remember: X" becomes note X, and "slow dream" waits until it is stopped. The workflow:

1. Add a separate `dream-model`. The chat default stays `fixture-model`.
2. Settings → Dreaming shows the destination disclosure, enable and save, then reload and confirm both settings persisted.
3. Dream now completes with "1 sources · 1 saved". The source disclosure, opened with the keyboard, shows the original message.
4. Memory shows the note as `Dreaming` with its source message.
5. A later chat recalls the note. After a manual correction it recalls the corrected text and shows `User editor`. After deletion, nothing is recalled.
6. Stop cancels a running dream.
7. Revoking memory access blocks Dream now with an explanation.
8. Removing the dreaming model shows the unavailable state and disables Dream now, with no fallback.

## Live model

`npm run test:live:dreaming` runs `scripts/live-dreaming-check.ts`. It copies only the default provider connection (encrypted) and model selection into an empty temporary desktop profile. It sends synthetic messages and deletes the profile afterwards. The user's real history, memory and connectors are never read or changed, and dreaming was never enabled on the real profile.

Before each recall question, the script restarts Electron and removes that isolated profile's transcript, so the answer can only come from recalled memory. This setup was added after the first attempt answered from the chat history still in context.

- **Provider:** OpenRouter, `openrouter/free`. It is also the dreaming model, because it is the only one copied.
- **Synthetic input:** a project codename, a Friday preference, and a one-time code with the instruction "never keep it".

| Step                                                                               | Uninterrupted run (5th of 6)                                                | Across runs                                                                                                                        |
| ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Isolated profile, dreaming off, no memory or connectors                            | Passed                                                                      | Passed every time                                                                                                                  |
| Separate dreaming model and consent                                                | Passed                                                                      | Passed every time                                                                                                                  |
| Stop cancels without saving                                                        | Passed                                                                      | Passed. The cancel came before the provider request was sent; aborting an in-flight provider request is covered by unit tests only |
| Live dream saves sourced notes, cited and readable through `/api/dreaming/sources` | Passed: "Project codename: Cobalt Heron", "Prefers status notes on Fridays" | Passed every time, with 2–3 notes                                                                                                  |
| One-time code not kept                                                             | Passed                                                                      | **Failed in 2 of 6 dreams.** The code was saved as a note                                                                          |
| Recall from memory alone in a later chat                                           | Passed                                                                      | Passed in both runs that isolated recall                                                                                           |
| Manual correction is recalled and becomes user-owned                               | Passed                                                                      | Passed                                                                                                                             |
| Forgetting stops recall and is not relearned on a re-dream                         | Passed                                                                      | One earlier attempt had its re-dream end `failed` before error codes were captured; not reproduced                                 |

**Verdict.** Live extraction, recall, correction and forgetting passed in an uninterrupted run. Secret retention is a real quality gap on this model. The spec defers automatic sensitive-data classification, so it is a documented limitation, not something the runtime guards against. The free router's behaviour varies between runs. Release acceptance should repeat this with the chosen production dreaming model.

## Not verified

- Aborting an in-flight provider request through Stop, live.
- Foreground interruption and the idle timer, live. Both are covered by deterministic tests.
- Live structured-output fallback through an OpenAI-compatible or local server. Only the fixture adapter covers it.
- Platforms other than macOS.
- Visual and keyboard review by the UI owner. The pane reuses the existing Settings layout. On it, the consent checkbox renders above its label, and "Bot to dream for" resets when the tab changes.
