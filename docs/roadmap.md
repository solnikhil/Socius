# Product roadmap additions

Status: planned, not implemented or assigned. These additions complement the [Notion roadmap](https://app.notion.com/p/3f910c43ad3e81198b7bdf7be7bf6b06) and [team handoff](team-handoff.md); checked foundation items there remain separate from the new behavior below. The user owns UI/visual decisions. New work needs coordinated runtime/contracts and verified acceptance before its checkbox is ticked.

The [complete feature specification](specs/product-expansion.md) maps all ten requested items to detailed work packages, dependencies, failure/recovery behavior and acceptance tests. Merging that spec does not complete the features.

## Orchestration and bot capabilities

- [ ] **A07 — Approved delegation from Socius's direct chat — highest priority in these additions.** Socius can propose a task for a named specialist, show the exact task and context for approval each time, dispatch only that approved work, and bring the attributed answer back to the originating chat. Support progress, cancel/failure/retry and durable task/approval links. Each bot retains its model, private context and permissions; delegation approval does not approve the specialist's external writes. Existing group delegation does not complete this item. Coordinate approval persistence with A04 without restoring board execution.
- [ ] **A03 — Scheduled routines.** Example: “Every Monday, have Planner draft my week.” Each private routine is off until explicitly enabled, has persisted timezone/schedule and missed-run policy, and exposes its attempts/results in Activity. Existing [Issue #10](https://github.com/solnikhil/Socius/issues/10) owns this work together with A04 durable execution and A05 quiet proactivity; do not open a duplicate routine engine/workstream.
- [ ] **A08 — Permissioned web search.** Allow a user to grant/revoke web search per bot so researchers and analysts can retrieve fresh sources. Select a reviewed search adapter, return attributable source links, enforce scope and budgets in the runtime, and treat fetched content as untrusted data. Grants are checked for direct, group, delegated and scheduled calls. Search is separate from browser control or permission to write to websites; templates can request access but cannot grant it.

## Finding and working with conversations

- [ ] **U07 — Search all chats and memory.** Search direct/group transcripts and permitted private memory with bot/speaker attribution, context snippets and links to the exact source. Support requests like “that thing Writer said about pricing.” Reconcile edits/deletions in the index and preserve sharing boundaries; a user search does not grant one bot every other bot's memories. Local full-text search is the baseline; semantic search is a separate extension.
- [ ] **U08 — Edit/resend and branch from any point.** Correct a prompt or branch from an earlier turn without starting over. Preserve original messages and downstream replies as explicit history/branches, make the active branch clear, and define group-turn retry behavior. Regeneration must not blindly replay tools, approvals, external writes or completed specialist work; changed actions require fresh approvals.
- [ ] **U09 — Pin important replies.** Pin/unpin plans and decisions inside their chat and provide a persistent, navigable pinned-replies list. Pins survive restart, follow message/branch/deletion rules and do not automatically become private memory or expand sharing.
- [ ] **U10 — On-device composer dictation.** Offer microphone input in the desktop message box, transcribe locally, and let the user edit text before sending. Handle microphone permission, listening/stop/cancel/error and unavailable-platform states. Validate that the selected OS/local recognition path actually stays on device; never silently fall back to cloud transcription. This is distinct from E05 Indian-language voice/TTS integrations.
- [ ] **U11 — Image and PDF attachments.** Accept drag/drop and file selection for images/PDFs alongside text. Use explicit provider/model input capabilities and a bounded validated ingestion path; show attachment previews, limits, processing/errors and clear unsupported-model behavior. Preserve attachments across restart/branching; send only permitted inputs to the chosen provider. Coordinate PDF parsing/fallback with U02 rather than duplicating it; multimodal support is not implied by ordinary text or tool support.

## Cost, usage and bot health

- [ ] **O01 — Per-bot usage, cost and monthly cap.** Persist provider-reported input/output/cached-token usage with model, bot and run attribution; show which bots consume the most tokens and estimated cost by period. Include chat, group contributions, direct delegation, Dreaming and routines without double counting parent/child calls. Separate measured usage, estimates and unavailable pricing/usage. Provide a configurable monthly cap with explicit units, reset timezone/date and a defined policy for in-flight calls, retries and unknown prices. Enforce allowance/reservation checks in the runtime across every call path; a UI warning alone is not a cap. Preserve history through price/model changes.
- [ ] **O02 — Inspectable bot health.** Combine reaction feedback, failed-reply rate and usage frequency into an understandable per-bot view that helps the user choose bots to rewrite or delete. Show time window, counts/denominators, sample size, recent trends and contributing signals; distinguish provider/setup failures and intentional cancellations from bot-quality failures. Avoid a misleading opaque score for lightly used bots. Link to relevant replies and editing/deletion controls; never automatically rewrite or delete bots on the strength of this view.

## Dependencies and acceptance

Direct delegation is the highest-priority new orchestrator gap identified by the user. Coordinate it with A04's durable approval/action model. Routines already belong to Issue #10. Usage accounting/budget hooks must cover both that work and [Dreaming #8](https://github.com/solnikhil/Socius/issues/8) without making either an implicit permission grant. Search, branches, pins and attachments need agreed message/source identities and deletion rules. Dictation remains local and separately validated from cloud voice services.

These are roadmap entries, not newly assigned implementation issues or promises that the capabilities exist. Each work package needs focused API/runtime tests, relevant UI acceptance and honest implemented-versus-planned documentation before integration. Keep shared DTOs and runtime hooks coordinated with ongoing workstreams.
